# ServicePromise AI

Prepare a small supplier catalogue, inspect the source evidence and account for every delivered item.

**Hosted pilot:** https://api-servicepromise-mr-2026.azurewebsites.net/

**Source:** https://github.com/MaciejR/servicepromise-ai

The catalogue workflow supports a context-aware rules baseline and operator-protected Azure OpenAI. Payments and per-item refund calculations in this workflow are **simulated**. PayPal Sandbox has not been connected to catalogue jobs. This is a feasibility MVP, not a production payment platform or a completed hackathon submission.

## Try the hosted pilot

1. Use the included example or upload/paste a UTF-8 CSV (up to 20 products, 256 KiB).
2. Select the product currency and the rules baseline. Azure requires the private operator token and incurs model usage; the token stays in UI memory.
3. Check the quote. Invalid rows are excluded before the simulated payment.
4. Select **Simulate payment & process**.
5. Inspect the product outcomes and expand an item to see source evidence and validation errors.
6. Download accepted products as draft CSV and the JSON evidence report.

The included example has four rows: one excluded before quoting, two delivered, and one undelivered after a repair attempt. The service quote is USD 3 and simulated refund eligibility is USD 1. No money moves.

The latest job capability is held in session storage. Reloading the same tab restores it. There are no user accounts, cross-device recovery or production authentication. Do not upload confidential customer data to this public pilot.

## Contract

Input header:

```csv
source_id,sku,name,price,currency,supplier_text
```

Source SKU, price and currency are authoritative and preserved. Color and material are normalized from a small explicit vocabulary, with source evidence. Missing, conflicting or unsupported attributes prevent acceptance. There is one initial attempt and at most one repair. Undelivered items are eligible for their entire individual service fee; complete non-delivery means a full simulated refund.

Service fees are in USD; product prices retain their source currency. Exporting does not convert currencies. Confirm that your store uses the same product currency. The draft Shopify CSV profile follows documented headers but has **not** been tested by importing into a store.

Acceptance checks a limited source contract; it does not establish the physical truth of a product claim. The rules baseline and real Azure model both matched all 60 provisional synthetic labels. This experiment did not establish an AI advantage, customer demand or human time savings. See the [pilot results](docs/CATALOG_PILOT_RESULTS.md) and [data provenance](examples/catalog/PROVENANCE.md).

## Run locally

Python 3.12+ and Node.js 22.12+ are required.

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

In a second terminal:

```bash
cd frontend
npm ci
npm run dev
```

Open http://localhost:5173. Vite proxies `/api` to port 8000. Keep `PAYMENT_MODE=demo` for catalogue jobs. Configure Azure OpenAI and a random operator token of at least 32 characters on the backend to enable protected real-model extraction. Never put secrets in a `VITE_` variable or commit `.env`.

## Durable processing and deployment

Catalogue jobs use separate SQLite tables and an additive migration. The first migration creates an online backup of the existing file database. The worker checkpoints each item and reserves attempts before external calls; startup recovers interrupted jobs. Completed items and final settlements are not regenerated by repeated checkout requests. The source, vocabulary, policy and quote are snapshotted per job.

**Exactly one instance and one application process are supported.** Catalogue routes return 503 for a PostgreSQL configuration. Startup recovery assumes process exclusivity. Move to a proper distributed worker/lease design before scaling. Jobs have a ten-minute processing budget. If the app is unavailable, recovery and simulated settlement occur when it returns.

Azure App Service hosts both API and compiled frontend. Production SQLite lives at `/home/servicepromise/servicepromise.db`; keep persistent storage enabled. Build the frontend, ZIP `backend/app`, runtime requirements, `startup.sh` and `frontend/dist` under `static/`, then deploy with App Service remote build. No local `.env` or database belongs in the deployment ZIP.
